### Проблемы

#### S1 — Дата-артефакт в тексте выдержки (frontend bug или data artifact)

**Наблюдение:** Источник «Multilateral trading facilities and organised trading facilities | FCA» показывает выдержку в виде:
```
Jul 5, 2023 — MTFs and OTFs facilitate the arranging and execution of transactions
in financial instruments on a 'multilateral system', which means any ...Read more
```

Сохранённая выдержка в данных:
```
"MTFs and OTFs facilitate the arranging and execution of transactions in financial instruments
on a 'multilateral system', which means any system in which multiple third-party buying and
selling interests in financial instruments are able to interact in the system."
```

**Проблема:** Перед текстом добавлена дата «Jul 5, 2023 —» которой нет в `excerpts[]`, и текст обрезан с «Read more». Возможные причины:
- Frontend делает live-fetch URL для preview (Google-snippet формат) вместо отображения хранимых excerpts
- Или excerpt хранится с этим артефактом в данных

**Действие:** UX-разработчику проверить, используются ли `excerpts[]` из API или происходит live URL preview. Если первое — проверить данные через API endpoint для этого источника.

#### S2 — Нет фильтра для типа «Другое»

**Наблюдение:** В фильтр-кнопках отсутствует «Другое». Источники с `type: "other"` не фильтруются отдельно, но входят в «Все».

**Действие:** UX-разработчику — добавить кнопку «Другое» или убедиться, что это намеренный дизайн-выбор.

#### S3 — Расхождение меток типа: бейдж vs. кнопка фильтра

| Тип в данных | Кнопка фильтра | Бейдж в списке |
|-------------|---------------|----------------|
| `government` | «Регулятор» | «Правит.» |
| `rulebook` | «Правила биржи» | «Правила» |

**Действие:** UX-разработчику — унифицировать либо сократить метки, либо использовать одно и то же слово везде. Предложение: «Правила биржи» → «Правила» или наоборот.

### Критические проблемы

#### S4 — «Fetched web page» как заголовок источника (data gap в пайплайне)

**Наблюдение:** Источник `https://www.handbook.fca.org.uk/handbook/UKLR/22/` отображается как «Fetched web page» вместо правильного заголовка «UKLR 22 — Continuing obligations».

**Подтверждено в данных** (`3A_raw.json`):
```json
{
  "url": "https://www.handbook.fca.org.uk/handbook/UKLR/22/",
  "title": "Fetched web page",
  "field": "instrument_requirements"
}
```

Проблема именно в данных — Level 3 пайплайн не смог получить заголовок страницы при сборе данных и сохранил placeholder `"Fetched web page"`.

**Известные источники с "Fetched web page" в L3 GB/LSE_Main_Market/equity_shares:**
- `https://www.handbook.fca.org.uk/handbook/UKLR/22/` — должно быть «UKLR 22 — Continuing obligations»
- `https://www.legislation.gov.uk/uksi/2024/105/contents` — должно быть «The Public Offers and Admissions to Trading Regulations 2024»

**Масштаб:** Неизвестен — проблема может присутствовать в любых L3 citations по всем юрисдикциям, где пайплайн не смог получить заголовок страницы.

**Зона ответственности:** Пайплайн данных. Нужен catchup-скрипт, который перезапрашивает заголовки для всех citations с `title == "Fetched web page"`.

#### S5 — Отсутствует поле `type` во всех L3 citations (data gap в пайплайне)

**Наблюдение:** Все L3 источники отображаются с бейджем «ДРУГОЕ» — независимо от типа документа.

**Подтверждено в данных** (`3A_raw.json`): ни у одного из 6 citations нет поля `type`. Пример:
```json
{
  "url": "https://docs.londonstockexchange.com/.../admission-and-disclosure-standards_1.pdf",
  "title": "ADMISSION AND DISCLOSURE STANDARDS",
  "field": "instrument_requirements"
  // ← нет поля "type"
}
```

Это правило биржи (`rulebook`), но отображается как «ДРУГОЕ».

**Причина:** Catchup-скрипт `run_source_classifier_catchup.py` при запуске обрабатывал L1/L2 источники (в `jurisdiction_card.json` и `venue_card.json`). L3 citations хранятся в `3A_raw.json`/`3B_raw.json`/`3C_raw.json` — они не были охвачены скриптом.

**Масштаб:** Все L3 cells по всем юрисдикциям. Тип «ДРУГОЕ» показывается вместо реального типа у каждого источника каждой ячейки.

**Зона ответственности:** Пайплайн данных. Нужен catchup-скрипт для L3 citations.

## Рекомендуемые следующие шаги (пайплайн)

### Приоритет 1 — S5: `type` для L3 citations
Расширить `run_source_classifier_catchup.py` (или написать отдельный скрипт) для классификации `type` в `citations[]` полей `3A_raw.json`, `3B_raw.json`, `3C_raw.json` по аналогии с тем, как это делается для L1/L2.

### Приоритет 2 — S4: «Fetched web page» titles
Написать catchup-скрипт, который:
1. Сканирует все `3A/3B/3C_raw.json` по всем юрисдикциям
2. Находит citations с `"title": "Fetched web page"`
3. Пытается получить заголовок из `<title>` HTML-страницы по URL
4. Обновляет title в данных

### Приоритет 3 — S1: Диагностика excerpt artifact
Проверить через API endpoint `/api/cells/{cell_id}/citations` или эквивалент — как именно возвращаются excerpts для источника с URL `https://www.fca.org.uk/firms/authorisation/wholesale-markets/mtfs-otfs`. Если в API-ответе дата уже присутствует — проблема в данных, если нет — frontend добавляет её сам.

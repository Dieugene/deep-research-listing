## F1 — NESTED секции 3B/3C не рендерятся

**Критичность: 🔴 Высокий**

**Что происходит:** Фронтенд рендерит секции контента в формате «FLAT» (`{description, source}`), но игнорирует секции в формате «NESTED» (`{subkey: {description, source}}`). Последние молча пропускаются.

**Затронутые секции в 3B** (одинаковы для всех ячеек):
- `suspension` — содержит `{procedure, grounds, duration_limits, disclosure}`
- `continuing_obligations` — содержит `{periodic_reporting, compliance_confirmation, ...}`
- `delisting_compulsory` — содержит `{grace_period, procedure, grounds, disclosure}`
- `delisting_voluntary` — содержит `{procedure, conditions, shareholder_approval}`
- `terminology` — содержит `{suspension_local_term, delisting_local_term, source}`

**Затронутые секции в 3C** (одинаковы для всех ячеек):
- `sanctions` — содержит `{regulator_sanctions, disciplinary_procedure, ...}`
- `monitoring_regime` — содержит `{issuer_reporting_to_exchange, mechanisms, ...}`
- `enforcement_practice` — содержит `{general_approach, recent_examples}`

**Объём скрытых данных:**

| Фаза | Ячейка | Скрытая секция | Цитации |
|------|--------|----------------|---------|
| 3B | EQUITY-1 | suspension | 1 src · 2 exc |
| 3B | EQUITY-1 | continuing_obligations | 2 src · 3 exc |
| 3B | BOND-1 | suspension | 1 src · 1 exc |
| 3B | FUND-1 | delisting_voluntary | 1 src · 0 exc |
| 3B | FUND-1 | continuing_obligations | 1 src · 1 exc |
| 3B | FUND-2 | suspension | 2 src · 1 exc |
| 3B | DR-1 | continuing_obligations | 1 src · 0 exc |
| 3B | EQUITY-3 | terminology | 1 src · 1 exc |
| 3B | EQUITY-3 | continuing_obligations | 2 src · 0 exc |
| 3B | EQUITY-3 | delisting_voluntary | 1 src · 0 exc |
| 3C | EQUITY-1 | enforcement_practice | 1 src · 3 exc |
| 3C | BOND-1 | sanctions | 1 src · 1 exc |
| 3C | BOND-1 | enforcement_practice | 1 src · 1 exc |
| 3C | FUND-1 | sanctions | 1 src · 1 exc |
| 3C | DR-1 | monitoring_regime | 1 src · 1 exc |
| 3C | ATT-BOND | enforcement_practice | 1 src · 1 exc |
| 3C | EQUITY-3 | sanctions | 1 src · 1 exc |

**FLAT секции работают корректно:** `additional_findings`, `common_obligations_common`, `common_monitoring_common`.

**Исправление:** В компоненте рендеринга секций контента добавить обработку NESTED формата: конкатенировать описания субключей или рендерить каждый субключ отдельным блоком.

## F2 — Вкладка «Исключение» показывает содержимое 3A

**Критичность: 🔴 Высокий**

**Что происходит:** При переходе на вкладку «Исключение» (`?view=tabs&phase=exclusion`) фронтенд не переключается на данные из `3C_raw.json` — вместо этого отображается содержимое вкладки «Допуск» (3A).

**Подтверждено для:** EQUITY-1, BOND-1. По архитектуре затрагивает все ячейки с 3C файлами.

**Что показывается неправильно:**
- Заголовки секций из 3A: «Вторичный допуск», «Требования к инструменту», «Общий обзор допуска»
- Источники из 3A: например, «3 источника · 6 выдержек» для instrument_requirements (вместо 3C секций sanctions/enforcement_practice)

**Что должно показываться (из 3C):**
- `additional_findings`, `sanctions`, `monitoring_regime`, `enforcement_practice`, `common_monitoring_common`

**Исправление:** Исправить маппинг `phase=exclusion` → загрузка `3C_raw.json` на бэкенде или роутинг в логике фазы. Матричный вид корректно использует 3C данные, значит баг изолирован в tab-view рендеринге.

## F3 — Параметры дублируются под каждой секцией (section_keys игнорируются)

**Критичность: 🔴 Высокий**

**Что происходит:** На страницах ячеек **все параметры** из `pass2_ru.json` показываются под **каждой** секцией контента, вместо фильтрации по полю `section_keys`.

**Пример (LSE/bond, вкладка Допуск):**
```
Вторичный допуск
[текст секции]
П14 П16 П19 ADDITIONAL_1 ADDITIONAL_3  ← ВСЕ параметры

Требования к инструменту
[текст секции]
П14 П16 П19 ADDITIONAL_1 ADDITIONAL_3  ← ВСЕ параметры (дубликат!)

Общий обзор допуска
[текст секции]
П14 П16 П19 ADDITIONAL_1 ADDITIONAL_3  ← ВСЕ параметры (дубликат!)
```

**Данные содержат правильную разбивку.** Пример из `pass2_ru.json`:
```json
{
  "param_id": "П16",
  "param_label_ru": "Проспект / информационный документ",
  "section_keys": ["admission_overview", "disclosure_at_admission"]
}
```
П16 должен показываться только под секциями `admission_overview` и `disclosure_at_admission`.

**Исправление:** В компоненте отображения параметров добавить фильтр: `params.filter(p => p.section_keys.includes(currentSection))`.

## F4 — Дублирование: `admission_architecture` и `admission_architecture_ru`

**Критичность: 🔴 Высокий**

**Что происходит:** На странице юрисдикции в разделе «Архитектура допуска» отображается **два текста подряд**: русский (`admission_architecture_ru`), затем английский (`admission_architecture`).

**Данные:** Оба поля заполнены в `jurisdiction_card.json` — это корректно.

**Диагноз:** Фронтенд рендерит оба поля вместо приоритизации `_ru`.

**Исправление:**
```js
// Было:
{card.admission_architecture}
{card.admission_architecture_ru}

// Должно быть:
{card.admission_architecture_ru ?? card.admission_architecture}
```

## F5 — `contradictions.resolution` (EN) вместо `resolution_ru`

**Критичность: 🔴 Высокий**

**Что происходит:** В разделе L4 «Противоречия» поле «Разрешение» отображается на английском.

**Данные содержат русский текст:**
```json
{
  "resolution": "From 2013–2014, the FCA responded...",
  "resolution_ru": "В 2013–2014 годах FCA ответила на скандалы..."
}
```
Поле `resolution_ru` заполнено, но фронтенд читает `resolution`.

**Исправление:**
```js
// Было:
{record.resolution}

// Должно быть:
{record.resolution_ru ?? record.resolution}
```

## F6 — Сырой ключ `common_obligations_common` как заголовок секции

**Критичность: 🟡 Средний**

**Что происходит:** На вкладке «Поддержание» одной из ячеек заголовок секции отображается как сырой технический ключ `common_obligations_common` вместо читаемой метки.

**Причина:** Ключ отсутствует в `SECTION_LABELS` в `backend/core/labels.py`. Бэкенд возвращает сырой ключ как fallback.

**Исправление:** Добавить в `backend/core/labels.py`:
```python
SECTION_LABELS = {
    ...
    "common_obligations_common": "Общие обязательства",
    "common_monitoring_common": "Общий мониторинг",
    ...
}
```

## F7 — `notes` без приоритета `notes_ru`

**Критичность: 🟡 Средний**

**Что происходит:** Блок «Примечания» на странице юрисдикции показывает текст на английском. Бэкенд поддерживает `notes_ru` в модели `JurisdictionCard`, но фронтенд не применяет приоритет `_ru`.

**Примечание:** Возможна двойная причина — если `notes_ru` отсутствует в данных, задача уходит в pipeline (P9). Если `notes_ru` присутствует, но фронтенд его не использует — это баг фронтенда.

**Исправление (фронтенд):**
```js
{card.notes_ru ?? card.notes}
```

## F8 — Дата-артефакт в тексте выдержки

**Критичность: 🟡 Средний (требует диагностики)**

**Что происходит:** Одна из выдержек на вкладке «Источники» (L1) отображается с датой-префиксом:
```
Jul 5, 2023 — MTFs and OTFs facilitate the arranging and execution...
```
В хранимых данных этой даты нет — `excerpts[]` содержит только чистый текст.

**Гипотезы:**
1. Фронтенд делает live-fetch URL для preview вместо использования хранимых `excerpts[]`
2. Дата записана в данных но не была обнаружена при проверке

**Действие:** Проверить через API endpoint какой контент возвращается для данного источника. Если `excerpts[]` в API-ответе чистые — баг во фронтенд-компоненте отображения выдержек.

## F11 — `VENUE_TYPE_LABELS` не находит lowercase ключи

**Критичность: 🟡 Средний**

**Что происходит:** После нормализации строк тип площадки приходит в lowercase (`"regulated_market"`, `"exchange_regulated"`), но `VENUE_TYPE_LABELS` в бэкенде содержит ключи в другом регистре. Совпадение не находится.

**Действие:** В `backend/core/labels.py` добавить lowercase ключи в `VENUE_TYPE_LABELS` и обработчик для `exchange_regulated`.

## F12 — Source pills в матрице отсутствуют

**Критичность: 🟢 Низкий / ⚠️ К уточнению**

**Что происходит:** В матричном представлении ячейки (`?view=matrix`) каждая клетка показывает параметры и индикатор «данные есть», но не показывает источники/citations непосредственно в ячейке.

**Контекст:** Неизвестно, является ли это намеренным поведением (матрица = упрощённый вид без источников) или пропущенной функциональностью.

**Действие:** Уточнить у дизайнера/продукт-овнера: нужны ли source pills в ячейках матрицы или это вне скоупа данного вида.

## 1. Страница юрисдикции: /jurisdictions/Великобритания

### 🔴 Баг #1 — Двойное отображение "Архитектура допуска"

**Что видно в интерфейсе:**
Два абзаца подряд — сначала русский, затем английский:

> *Раздельная модель «двух ворот»: FCA (компетентный орган по FSMA 2000, Часть VI) ведёт Official List...* [RU]
>
> *Separate two-gate model: the FCA (UK competent authority under FSMA 2000 Part VI) maintains the Official List...* [EN]

**Данные (jurisdiction_card.json):**
- `admission_architecture` → английский текст
- `admission_architecture_ru` → русский текст (оба поля заполнены)

**Диагноз:** Фронтенд рендерит оба поля вместо только `_ru`.

**Исправление:** Показывать только `admission_architecture_ru`, скрыть `admission_architecture`.

## 3. Страницы ячеек (все ячейки)

### 🔴 Критичный баг #3 — Параметры дублируются под каждой секцией

**Что видно:** На каждой странице ячейки параметры показываются **под каждой секцией**. Пример для LSE/bond:

```
Вторичный допуск
[текст секции]
П14 ... П16 ... П19 ... ADDITIONAL_1 ... ADDITIONAL_3  ← ВСЕ параметры

Требования к инструменту
[текст секции]
П14 ... П16 ... П19 ... ADDITIONAL_1 ... ADDITIONAL_3  ← ВСЕ параметры (дубликат!)

Общий обзор допуска
[текст секции]
П14 ... П16 ... П19 ... ADDITIONAL_1 ... ADDITIONAL_3  ← ВСЕ параметры (дубликат!)

[... ещё 5 секций с теми же параметрами ...]
```

**Данные (pass2_ru.json):**
У каждого параметра есть поле `section_keys[]`, указывающее, к каким секциям он относится:
```json
{
  "param_id": "П16",
  "param_label_ru": "Проспект / информационный документ",
  "section_keys": ["admission_overview", "disclosure_at_admission"]
}
```

**Диагноз:** Фронтенд показывает все параметры под всеми секциями, игнорируя `section_keys`. Нужно фильтровать: показывать параметр только под секциями, перечисленными в его `section_keys`.

### 🔴 Пробел данных #6 — Весь текст секций на английском

**Что видно** (пример для LSE/bond, секция "Требования к инструменту"):
> *As detailed above with exact rules: £200,000 min aggregate market value (UKLR 3.2.7R)...*

**Что видно** (LSE/equity, секция "Требования к инструменту"):
> *Free Float: At least 10% of shares must be in "public hands" at admission (UKLR 5.5.2R)...*

**Данные (3A_raw.json):**
```json
{
  "content": {
    "instrument_requirements": {
      "description": "Free Float: At least 10%..."  ← только EN, нет description_ru
    }
  }
}
```

**Диагноз:** Пайплайн не переводит текст секций Level 3 (3A/3B/3C). Только параметры переводятся через `pass2_ru.json`. Это архитектурный пробел — требует новой задачи пайплайна для перевода `description` → `description_ru` во всех секциях.

### 🟡 Баг фронтенда #4 — Необработанный ключ секции `common_obligations_common`

**Что видно** (LSE/bond, фаза "Поддержание"):
```
Дополнительные сведения
[текст]

common_obligations_common       ← RAW KEY, не метка!
[текст]
```

**Данные:** Ключ `common_obligations_common` — валидный ключ секции в 3B_raw.json.

**Диагноз:** Этот ключ отсутствует в `SECTION_LABELS` (backend/core/labels.py). Бэкенд возвращает сырой ключ как `section_label` при отсутствии совпадения.

**Исправление:** Добавить в `backend/core/labels.py`:
```python
SECTION_LABELS = {
    ...
    "common_obligations_common": "Общие обязательства",
    ...
}
```

### 🟡 Пробел данных #10 — `ADDITIONAL_X` параметры: метка на английском

**Что видно:**
```
ADDITIONAL_1 Entire class must be included in the application   ← EN label
Заявка должна относиться ко всем ценным бумагам...              ← RU value ✅
```

**Данные (pass2_ru.json):**
```json
{
  "param_id": "ADDITIONAL_1",
  "param_label": "Entire class must be included in the application",
  "param_label_ru": null  ← отсутствует для ADDITIONAL-параметров
}
```

**Диагноз:** Параметры `ADDITIONAL_X` не получают русский перевод метки в пайплайне. Это пробел Pass 2 — ADDITIONAL параметры генерируются из дополнительных находок и не имеют стандартного `param_label_ru`.

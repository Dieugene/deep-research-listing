**Дата:** 2026-03-11  
**От:** Архитектор пайплайна  
**Кому:** Tech Lead  
**Контекст:** Pass 2 завершён (599 parameter_value по 25 ячейкам). Далее — перевод на русский и отображение во Viewer.

---

## 1. Перевод на русский

### Что переводить

Текстовые поля в каждом pass2.json:
- `value` (описание значения параметра)
- `calculation_methodology`
- `alternatives`
- `variations`
- `linkages` (описательная часть)
- `source` — **НЕ переводить** (названия законов и глав rulebook остаются на языке оригинала)

Также: `parameter_name` — перевод берётся из словаря параметров (П01–П35 уже имеют русские названия). Не переводить через LLM — подставлять из словаря.

### Как переводить

LLM-батч. Один вызов на ячейку (не на отдельный parameter_value — иначе слишком много мелких вызовов). На вход — весь pass2.json ячейки. Задание:

```
Translate the following parameter descriptions from English to Russian.
Preserve all technical terms, rule numbers, and legal references 
in their original language (do not translate "UKLR 6.14.3R", 
"Chapter 8", "Rule 8.08" etc.).
Translate only the descriptive text.
Do not change the JSON structure — return the same structure 
with translated text fields.
Field "source" — do NOT translate, keep as is.
Field "parameter_id" — do NOT translate.
```

### Результат

`pass2_ru.json` рядом с `pass2.json` в той же директории. Та же структура, текстовые поля на русском, source и ID без изменений.

## 2. Отображение во Viewer

### Что показывать

Viewer уже отображает карточки юрисдикций (Level 1) и карточки площадок (Level 2). Добавить: данные Pass 2 по ячейкам.

### Навигация

Из карточки площадки (venue_card) пользователь видит список ячеек (тиры × классы инструментов). Клик по ячейке → экран параметров.

### Экран параметров ячейки

**Заголовок:** venue → tier → instrument_class. Цветовой индикатор validation_status (green / yellow / red).

**Содержание:** таблица параметров из pass2_ru.json (или pass2.json если перевод ещё не выполнен).

| Столбец | Источник | Примечание |
|---------|----------|------------|
| ID | parameter_id | П01, П02, ... или CANDIDATE_XX |
| Параметр | parameter_name (русский из словаря) | |
| Значение | value | Основное текстовое описание |
| Методика расчёта | calculation_methodology | Свёртываемый блок |
| Альтернативы | alternatives | Свёртываемый блок |
| Вариации | variations | Свёртываемый блок |
| Связки | linkages | Ссылки на другие parameter_id |
| Фаза ЖЦ | lifecycle_phase | admission / continuing / suspension / delisting |
| Источник | source | Название закона/правила |
| Статус | found / not_applicable / not_found | Цветовая индикация |

**Свёртываемые блоки:** по умолчанию показываются только ID, название, значение, фаза ЖЦ, статус. Остальные поля — по клику «развернуть» на строке.

**Фильтрация:**
- По статусу: показать только found / показать все
- По фазе ЖЦ: admission / continuing / все
- По категории параметра: количественные к инструменту / к эмитенту / качественные / инфраструктурные / ограничительные

**Цветовая индикация статуса параметра:**
- `found` — обычный текст
- `not_applicable` — серый, курсив
- `not_found` — серый, пометка «н/д»

**Цветовая индикация validation_status ячейки (в заголовке):**
- GREEN — зелёная точка
- YELLOW — жёлтая точка + подпись «источники не верифицированы»
- RED — красная точка + подпись «данные не получены» (экран параметров не показывается, только статус)

### CANDIDATE_XX параметры

Отображаются в той же таблице, но визуально отделены: после основных параметров словаря, с пометкой «параметр вне словаря (кандидат)». Серый фон или отдельная секция.

### Связки параметров

Если поле `linkages` содержит ссылку на другой parameter_id — отображать как кликабельную ссылку (скролл к соответствующей строке таблицы). Если связанный параметр в другой ячейке — ссылка с указанием ячейки.

### Данные, которых пока нет

- RED-ячейки: показывать в списке ячеек площадки, но с красным индикатором и без экрана параметров.
- Ячейки без pass2.json (не обработаны): показывать как «ожидает обработки».

## 3. Что НЕ делать сейчас

- Сравнительные таблицы между юрисдикциями (бессмысленно на двух).
- Загрузка в PostgreSQL (формат данных ещё может меняться при масштабировании).
- Типологизация конструкций как отдельный шаг (будет при загрузке в БД).
- Уровень 4 (проблемно-ориентированный анализ) — после решения о масштабировании.

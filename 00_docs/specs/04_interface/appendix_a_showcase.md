# Приложение А. Витринный слой и визуальный дизайн

**К документу:** Спецификация информационной архитектуры и визуальных шаблонов, v0.1  
**Дата:** 2026-03-05

---

## А1. Проблема и принцип

Основная спецификация описывает систему «изнутри» — как пользователь работает с данными. Но первый контакт с системой — это не работа. Это впечатление. Пользователь (особенно внешний — читатель доклада, руководитель, коллега из смежного подразделения) должен за первые 5–10 секунд понять три вещи:

1. **Масштаб:** здесь собрано что-то серьёзное.
2. **Глубина:** это не поверхностный обзор, а систематическое исследование.
3. **Качество:** за этим стоит профессиональная работа.

После чего он либо углубляется (авторы доклада), либо уходит впечатлённым (руководство, внешние читатели). Оба сценария — успех.

**Принцип:** Стартовая страница — не меню навигации, а витрина. Сначала — показать, потом — дать выбрать.

## А2. Стартовая страница: структура экрана

Стартовая страница состоит из двух зон: **витрина** (верхняя, на весь первый экран) и **навигация** (ниже, доступна по скроллу или по клику).

### А2.1. Витрина (первый экран, без скролла)

#### Центральный элемент: интерактивная карта мира

Карта мира с 47 подсвеченными юрисдикциями. Точки — площадки (65 точек, сгруппированных по юрисдикциям).

Визуальные свойства:
- Тёмный фон (тёмно-синий или графитовый — ассоциация с финансовой аналитикой, не с развлекательным контентом).
- Точки юрисдикций светятся (мягкое свечение, цвет — по кластерной принадлежности).
- Размер точки — пропорционален количеству площадок или объёму собранных данных.
- Hover по точке — всплывающая мини-карточка: название юрисдикции, количество площадок, правовая семья, кластер.
- Клик — переход к карточке юрисдикции.
- Линии связей между юрисдикциями одного кластера (тонкие, полупрозрачные) — создают визуальный паттерн, показывающий группировку.

При загрузке страницы — анимация: точки появляются последовательно по регионам (Европа → Азия → Америки → Африка/Ближний Восток), с мягким пульсом. Занимает 2–3 секунды, не больше.

#### Боковая панель: ключевые метрики

Справа от карты (или поверх неё, в зависимости от экрана) — блок метрик с крупными числами:

```
47 юрисдикций
65 торговых площадок
4 класса инструментов
~1000 режимов допуска
12 институциональных факторов
15 регуляторных проблем
```

Числа — крупный шрифт, акцентный цвет. Под каждым — одно пояснительное слово мелким шрифтом. Анимация при загрузке: числа «набираются» от 0 до значения (counter animation, ~1 секунда).

#### Нижняя часть первого экрана: мини-визуализации (sparklines)

Три–четыре горизонтальных мини-графика, показывающих характер данных:

1. **Распределение по правовым семьям:** горизонтальный stacked bar (common law / civil law / mixed / иное). Одна полоска, несколько цветов. Мгновенно видна структура.

2. **Заполненность данных:** прогресс-бар по этапам (маппинг: X%, факторы: Y%, справочные данные: Z%, аналитика: W%). Показывает, что система живая и наполняется.

3. **Распределение по кластерам:** горизонтальный bar chart — сколько юрисдикций в каждом кластере. Визуализирует, что кластеризация — не формальность, а рабочий инструмент.

Эти мини-визуализации — не интерактивные (или минимально). Их задача — за 3 секунды создать ощущение «здесь много структурированных данных».

#### Призыв к действию

Внизу первого экрана — два якоря:
- «Начать работу» (скролл к навигации или переход в справочник).
- «Как устроено исследование» (скролл к блоку методологии, см. А2.3).

### А2.2. Навигация (второй экран)

То, что описано в основной спецификации (п. 2.2), но визуально оформлено как четыре карточки с превью:

**Карточка «Справочник»:**
- Превью: миниатюра матрицы 4×5 с цветовой кодировкой (реальные данные, если есть; mock, если нет).
- Подпись: «Параметры листинговых режимов по юрисдикциям».
- Три иконки точек входа: от инструмента, от юрисдикции, от параметра.

**Карточка «Сравнительный анализ»:**
- Превью: миниатюра scatter plot кластеров (реальные данные).
- Подпись: «Группировка юрисдикций по институциональным условиям».

**Карточка «Проблемный анализ»:**
- Превью: список из 4 конфликтов (только заголовки), визуально оформленный как карта связей.
- Подпись: «Регуляторные проблемы и международный опыт их решения».

**Карточка «Бот»:**
- Превью: поле ввода с примером вопроса (placeholder): «В каких юрисдикциях free float ниже 15%?»
- Подпись: «Задайте вопрос по материалам исследования».

### А2.3. Блок методологии (третий экран, опционально)

Компактное описание исследования для внешнего читателя. Три–четыре абзаца + инфографика:

- Что исследовалось (допуск и листинг ценных бумаг в 47 юрисдикциях).
- Как (концептуальная модель → институциональные факторы → сбор данных → аналитика).
- Кто пользователь (авторы доклада Банка России).
- Зачем (основа для решений о калибровке российского регулирования).

Инфографика: пайплайн исследования (4 этапа) — визуальная последовательность с иконками.

## А3. Визуальный язык системы

### А3.1. Общий тон

**Финансовая аналитика, не академический доклад.** Система должна восприниматься как инструмент Bloomberg-класса по серьёзности, но с лучшей визуальной проработкой. Не «красивая презентация», а «серьёзный инструмент, который выглядит дорого».

**Ориентиры:** информационные панели крупных финансовых аналитических платформ; стилистика data journalism крупных медиа (Financial Times, The Economist); визуализации Тафти (высокая плотность информации при ясности).

### А3.2. Цветовая палитра

**Основа:** тёмная тема для витринного слоя (первое впечатление), светлая тема для рабочих экранов (справочник, таблицы — длительная работа). Переключатель тем — опционально, не приоритет.

**Акцентные цвета по функциям:**

| Функция | Цвет | Применение |
|---------|------|-----------|
| Кластер 1 | Синий (основной) | Точки на карте, метки кластера |
| Кластер 2 | Бирюзовый | — |
| Кластер 3 | Золотой/охра | — |
| Кластер 4 | Терракотовый | — |
| Кластер 5+ | Дополнительные приглушённые тона | — |
| Заполнено | Насыщенный синий | Ячейки матрицы 4×5 |
| Не заполнено | Светло-серый | — |
| Не применимо | Штриховка | — |
| Наднациональный минимум | Приглушённый индиго | Индикация EU-норм |
| Национальная надстройка | Основной цвет юрисдикции | — |
| Авторская шкала | Пунктирная рамка | Индикация Ф10 |

Примечание: конкретные hex-значения определяются при прототипировании. Здесь — принципы.

### А3.3. Типографика

**Заголовки:** рубленый шрифт с характером (не Inter, не Roboto). Варианты для рассмотрения: DM Sans, Outfit, Manrope, или (при ориентации на серьёзность) Söhne, Graphik. Выбирается при прототипировании.

**Основной текст:** читаемый гротеск. Source Sans 3, IBM Plex Sans, или пара к заголовочному.

**Числа и данные:** моноширинный или tabular figures (IBM Plex Mono, JetBrains Mono). Числа в таблицах выровнены по разрядам.

**Кириллица:** все выбранные шрифты должны иметь полноценную кириллическую поддержку. Это ограничивает выбор — учитывать при финальном решении.

### А3.4. Иконография

Минимальный набор иконок:

| Элемент | Иконка |
|---------|--------|
| Акции | Линейный график (или свеча) |
| Облигации | Горизонтальные линии (купоны) |
| Фонды | Круговая диаграмма |
| Депозитарные расписки | Документ со стрелкой |
| Источник/сноска | Номер в кружке |
| Институциональный контекст | Слои (overlay) |
| Связанные проблемы | Восклицательный знак в круге |
| Наднациональное | Звезда EU (или аналог) |

Стиль иконок — линейный (stroke), не заливочный. Единообразный вес линии.

## А4. Элемент «визуальной глубины» — матрица заполненности

Помимо карты мира, второй сильный визуальный элемент для витрины — **матрица заполненности** (можно разместить на стартовой странице как альтернативный вид или на отдельном экране «обзор данных»).

Это компактная визуализация всего массива данных в одном экране:

- Строки: 65 площадок (сгруппированы по юрисдикциям, отсортированы по кластерам).
- Столбцы: 4 класса инструментов × ключевые параметры (или просто 4 класса).
- Ячейки: цвет = заполненность (есть данные / нет / н.п.).

Результат: прямоугольник ~65×4 (или ~65×20 при детализации до параметров), где паттерн заполненности виден мгновенно. Это «small multiple на максимуме» — весь датасет в одном взгляде.

Hover по ячейке — название площадки + класс + статус. Клик — переход к карточке.

Эта визуализация решает задачу «показать глубину»: читатель видит не число «1000 ячеек», а реальную картину — какие области проработаны, какие нет, где плотность данных максимальна.

## А5. Адаптация к этапам заполнения

Витринный слой должен быть впечатляющим на каждом этапе, а не только при полном заполнении.

**Этап 1 (маппинг, 0–10% справочных данных):**
- Карта мира — все 47 точек активны (юрисдикции определены).
- Метрики: акцент на структурных показателях (юрисдикции, площадки, классы).
- Матрица заполненности — почти пустая, но видна структура (строки и столбцы размечены).
- Посыл: «масштабное исследование запущено».

**Этап 2 (институциональные факторы, 10–30%):**
- Карта мира — точки окрашены по кластерам. Линии связей появляются.
- Scatter plot кластеров — работает, показывает реальную группировку.
- Матрица заполненности — начинает заполняться.
- Посыл: «47 юрисдикций проанализированы по 12 факторам, видна структура».

**Этап 3 (справочные данные, 30–80%):**
- Матрица заполненности — основной визуальный элемент, показывает прогресс.
- Мини-визуализации на стартовой — содержательные (реальные распределения).
- Посыл: «систематический сбор данных по всем юрисдикциям».

**Этап 4 (аналитика, 80–100%):**
- Все элементы витрины работают на полных данных.
- Проблемный анализ — заполнен.
- Посыл: «исследование завершено, результаты доступны».

## А6. Примеры «впечатляющих» элементов для прототипирования

Следующие элементы выходят за рамки минимальной функциональности, но могут быть реализованы для усиления визуального эффекта. Приоритет — определяется при прототипировании.

**1. Анимированный переход «карта → scatter plot».** При переходе из витрины в сравнительный анализ точки юрисдикций «перелетают» с географических координат на координаты институциональных факторов. Одни и те же точки, разные оси. Это визуально демонстрирует суть конфигурационного подхода: география не определяет регуляторную модель.

**2. Параллельное сравнение «бок о бок».** Пользователь перетаскивает (drag) карточки юрисдикций в зону сравнения. Карточки выстраиваются рядом, одинаковые поля выравниваются. Тафти в чистом виде: adjacency enables comparison.

**3. «Рентген» матрицы 4×5.** При наведении на ячейку матрицы — остальные ячейки той же строки (фазы) или столбца (типа содержания) подсвечиваются по всем юрисдикциям. Пользователь видит: «как устроен мониторинг на фазе поддержания» — одна строка, 47 юрисдикций.

**4. «Пульс» обновлений.** На стартовой странице — лента последних обновлений данных (какая юрисдикция обновлена, что добавлено). Создаёт ощущение живой системы, а не статичного отчёта.

## А7. Техническая реализация витрины

| Элемент | Рекомендуемая технология | Альтернатива |
|---------|------------------------|-------------|
| Карта мира | D3.js (d3-geo) | Leaflet + custom tiles |
| Scatter plot / heatmap | D3.js или Plotly | Recharts (если React) |
| Анимации загрузки | CSS transitions + requestAnimationFrame | Framer Motion (React) |
| Counter animation | requestAnimationFrame | CountUp.js |
| Матрица заполненности | Canvas (при >1000 ячеек) или SVG (D3) | HTML table + CSS |
| Drag-and-drop сравнение | HTML Drag API или dnd-kit (React) | — |

Витрина должна загружаться быстро (<2 секунды до первого отображения). Тяжёлые визуализации (карта, scatter plot) — lazy load после первого экрана или по требованию.

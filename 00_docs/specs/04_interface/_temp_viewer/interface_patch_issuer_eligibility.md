# Патч к интерфейсу: карточка площадки (venue_card)

**Дата:** 2026-03-09  
**Основание:** Ревью пилота — некорректное отображение требований к эмитенту на уровне площадки; использование жаргонизма «ворота» вместо терминов концептуального ядра.

---

## 1. Терминология: замена «ворот»

| Было | Стало | Обоснование |
|------|-------|-------------|
| «Раздельные ворота: Да» | «Раздельный допуск эмитента и инструмента: Да» | Понятие В04 ядра. «Ворота» — калька с англ. «two-gate model», не устоявшийся русскоязычный термин. |
| «Описание требований к эмитенту» | Убрать (см. п. 2) | |

Поле `issuer_eligibility_separate` в venue_card переименовать в отображении:

```
Было:
  Раздельные ворота
  Да
  ∨ Описание требований к эмитенту
  [развёрнутый текст про конкретные требования по классам инструментов]

Стало:
  Раздельный допуск эмитента и инструмента
  Да
  Кто проводит: FCA (UKLA) — допуск эмитента; LSE — допуск инструмента
  Основание: FSMA 2000 Part VI, UK Listing Rules
```

---

## 2. Ограничение содержания блока

**Проблема:** блок «Описание требований к эмитенту» на скриншоте содержит:
- конкретные требования по классам инструментов (equity IPO, funds, debt)
- ссылки на специальные режимы (WVR Ch 8A, Biotech Ch 18A, SPAC Ch 18B)
- описание процедур (sponsor review, SFC authorisation, programme approval)

Это содержание ячеек уровня 3, не уровня площадки.

**Что допустимо на уровне площадки (venue_card):**

| Поле | Содержание | Пример |
|------|-----------|--------|
| `issuer_eligibility_separate` | Boolean: есть ли раздельная процедура | `true` |
| `issuer_eligibility_authority` | Кто проводит проверку эмитента | «FCA (UKLA)» |
| `instrument_admission_authority` | Кто проводит допуск инструмента | «LSE» |
| `legal_basis` | Правовое основание разделения | «FSMA 2000 Part VI» |

**Что убрать из venue_card:**
- Описание конкретных требований к эмитенту по классам
- Перечисление специальных режимов и их условий
- Описание процедуры для разных типов инструментов

Всё это находится (или будет находиться) в результатах запросов уровня 3 по соответствующим ячейкам.

---

## 3. Прочие термины для проверки

Проверить интерфейс на наличие иных жаргонизмов и привести к терминам ядра:

| Жаргонизм / калька | Термин ядра | ID |
|--------------------|------------|-----|
| «Ворота» | Раздельный допуск эмитента и инструмента | В04 |
| «Тир» | Уровень листинга | А05 |
| «Борд» | Торговая площадка (venue) или уровень листинга — зависит от контекста | А02 / А05 |
| «Листинговые правила» | Правила допуска / правила листинга (в зависимости от Г04) | — |
| «Делистинг» | Исключение (если нужен русский) или delisting (если англ. допустим) | Г07.4 |

Правило: в интерфейсе использовать русскоязычные термины ядра. Английские эквиваленты — в скобках или во всплывающей подсказке, не как основные.

**Дата:** 2026-03-19
**От:** Разработчик интерфейса
**Кому:** UX-дизайнер

## Предыстория

После восстановления полного потока источников (citations) из Parallel API в данных появились два новых поля, которых ранее не было. Они доступны для отображения, но требуют дизайн-решения.

Подробный отчёт пайплайна: `00_docs/reports/ux_handoff_sources_restored_2026-03-19.md`

---

## Поле 1: `confidence` в источниках (citations/sources)

### Что это
Уровень уверенности Parallel API в релевантности найденного источника. Три значения: `high`, `medium`, `low`.

### Где встречается
Во всех `citations[]` и `sources[]` на всех уровнях (L1–L4). Корреляция: `high` обычно означает наличие выдержек (excerpts), `low` — отсутствие.

### Пример данных
```json
{
  "url": "https://handbook.fca.org.uk/...",
  "title": "FCA Handbook",
  "type": "rulebook",
  "confidence": "high",
  "excerpts": ["Rule 5.5.2R: At least 10%..."]
}
```

### Варианты отображения
- **A)** Не показывать — пользователь сам оценивает по наличию выдержек
- **B)** Маленький индикатор рядом с источником (цветная точка или бейдж: `надёжно` / `средне` / `слабо`)
- **C)** Фильтр по confidence на вкладке источников (показать только high-confidence)

## Поле 2: `reasoning` в секциях контента

### Что это
Обоснование исследования — текст от Parallel API, объясняющий, как он пришёл к выводу по данной секции. Например: *"The analysis was derived from FCA Handbook UKLR 5.4 and cross-referenced with LSE ADS Schedule 1..."*

### Где встречается
В секциях контента `3A/3B/3C_raw.json`:
```json
{
  "content": {
    "instrument_requirements": {
      "description": "...",
      "description_ru": "...",
      "source": "...",
      "reasoning": "The analysis was derived from FCA Handbook..."
    }
  }
}
```

### Контекст использования
Reasoning помогает пользователю понять методологию исследования — почему LLM сделал именно такой вывод. Это инструмент верификации: если reasoning ссылается на конкретные нормативные акты, пользователь может проверить первоисточник.

### Варианты отображения
- **A)** Не показывать — текст технический, пользователю не нужен
- **B)** Expandable блок под секцией: «Как получен этот вывод ↓» с текстом reasoning
- **C)** Tooltip при наведении на иконку `ⓘ` рядом с заголовком секции
- **D)** Отдельная вкладка/режим «Методология» на странице ячейки

### Важно
Текст reasoning только на английском (перевод не планируется). Длина: обычно 1–3 предложения.

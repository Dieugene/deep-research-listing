Н-1 Dropdown «Справочник» исчезает при движении мыши к пунктам Баг

Между триггером «Справочник» и dropdown-блоком есть зазор — мышь его пересекает, срабатывает mouseleave, список скрывается раньше чем пользователь до него добирается.

Если dropdown на CSS (hover):

.dropdown {
  margin-top: -2px;  /* перекрыть зазор */
  padding-top: 6px;  /* визуальный отступ */
}

Если dropdown на JS (mouseleave/mouseenter):

let hideTimeout;
trigger.addEventListener('mouseleave', () => {
  hideTimeout = setTimeout(() => hideDropdown(), 150);
});
dropdown.addEventListener('mouseenter', () => clearTimeout(hideTimeout));
dropdown.addEventListener('mouseleave', () => hideDropdown());
Н-2 Флаги не отображаются на Windows (показываются коды «GB», «DE»…) Баг

Windows не поддерживает emoji-флаги нативно. Заменить emoji на <img> с flagcdn.com:

<img
  src="https://flagcdn.com/24x18/{iso_code_lowercase}.png"
  srcset="https://flagcdn.com/48x36/{iso_code_lowercase}.png 2x"
  width="24" height="18"
  alt="{country_name}"
  style="display:block"
/>

ISO-код — строчными: gb, de, hk и т.д. Контейнер флага — круглый div с overflow: hidden, img внутри с object-fit: cover; width: 100%; height: 100%.

Применить: список юрисдикций, карточка юрисдикции (шапка), карточка-превью на лендинге.

Список юрисдикций — /jurisdictions

С-1 Дублирование «civil law» в фильтрах правовой семьи Баг

Кнопки фильтра строятся динамически из данных без дедупликации — «civil law» появляется дважды. Исправить при формировании списка значений:

const families = Array.from(new Set(
  jurisdictions.map(j => j.legal_family.toLowerCase())
));
С-2 «Civil law» с заглавной буквы в строке Германии Высокий

Данные приходят с разным регистром. Нормализовать при отображении чипа правовой семьи — не трогая данные:

legalFamily.toLowerCase()

Карточка юрисдикции — /jurisdictions/[name]

К-1 Блок «Notes» выводится как параграф — оформить как секцию «Примечания» Высокий

Поле notes сейчас — обычный параграф сразу после регулятор-стрипа. Оформить как отдельную секцию внутри той же левой карточки: горизонтальный разделитель → заголовок «Примечания» → текст курсивом (паттерн arch-note из прототипа). Показывать только если поле не пустое.

К-2 Система источников — реинтегрировать после восстановления в пайплайне Высокий

Источники — критически важный элемент продукта. Только через них выполняется верификация отображаемых данных. Источники нужны по каждому блоку данных везде в интерфейсе, их отсутствие — не допустимо как финальное состояние.

Текущая ситуация: источники терялись в пайплайне сбора данных. Работа по их восстановлению ведётся параллельно. Как только источники появятся в данных — их нужно немедленно реинтегрировать в интерфейс.

Где отображать:

  • Блоки «Архитектура допуска», «Регулятор», «Примечания» — кнопка «N источников» в шапке блока + пронумерованный список внизу
  • Drawer регуляторного анализа — список источников в конце каждой записи
  • Карточка площадки — источники при каждом параметре

Правило по количеству (из ТЗ listing-research-dev-spec.html, раздел «Система источников»): 1–5 — показать все; 6–15 — collapse «показать ещё»; 16+ — drawer со списком и поиском.

Рекомендация: подготовить компонент источников заранее, чтобы при появлении данных интеграция была вопросом одного подключения, а не разработки с нуля.

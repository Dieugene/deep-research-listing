Задачи по аудиту данных: карточка юрисдикции

Источник: аудит разработчика · март 2026

Контекст: в ходе аудита разработчик выявил поля, которые есть в API и данных, но не отображаются в UI. Все они содержат ценную аналитическую информацию — игнорировать их не следует. Задачи сгруппированы по месту отображения.

Группа 1 — поля jurisdiction_card.json, рендеринга нет

А-1 listing_authority — орган листинга в регулятор-стрипе Высокий

Вкладка «Юрисдикция»

Поле содержит описание органа листинга — не всегда совпадающего с регулятором. Германия — наглядный пример: BaFin регулирует рынок, но листинговым органом является Börsengeschäftsführung (биржевое управление). Без этого разграничения пользователь делает неверный вывод об архитектуре допуска.

Добавить как дополнительный атрибут в горизонтальный регулятор-стрип — после типа, до правовой семьи:

Регулятор-стрип (до и после)
НаименованиеFinancial Conduct Authority (FCA)
Типcommission
Орган листинга ← новоеFinancial Conduct Authority (FCA)
Правовая семьяcommon law

Поле listing_authority — длинный текст, обрезать до первых ~60 символов с title-атрибутом для полного текста при hover. Если поле совпадает с названием регулятора — показывать как есть без сокращения.

А-2 market_types — типы рынков юрисдикции Низкий

Вкладка «Юрисдикция»

Массив типов рынков, присутствующих в юрисдикции: ["Regulated Market", "MTF (Freiverkehr)", "OTF"]. Полезен как быстрый справочник — не нужно изучать все площадки чтобы понять структуру.

Добавить как строку тегов в конец регулятор-стрипа, после правовой семьи:

Добавить строку в стрип
Типы рынков Regulated Market MTF OTF

Теги — нейтральный стиль (серый чип). Не кликабельны.

А-3 supranational_flag + supranational_framework — наднациональный контекст Средний

Вкладка «Юрисдикция»

Для юрисдикций-членов ЕС (supranational_flag === true) национальный режим существует внутри европейского. Игнорировать это — значит давать неполную картину. Пользователь должен знать, что немецкие требования к проспектам определяются EU Regulation 2017/1129, а не только BörsG.

Отображать как отдельный информационный блок на вкладке «Юрисдикция» — только если supranational_flag === true. Для UK, США, HK — блок не показывается.

Блок «Наднациональный контекст» (показывать условно)
Наднациональный контекст EU
European Union: Prospectus Regulation (EU) 2017/1129; MiFID II/MiFIR; MAR

Разместить под блоком «Архитектура допуска + Регулятор», в той же левой колонке, до блока метрик ВБ.

Группа 2 — метаполя level4.json, UI игнорирует

Контекст: все эти поля отображаются в drawer при клике на элемент таймлайна или строку списка. Карточка юрисдикции их не касается — только компонент drawer регуляторного анализа.

Б-1 resolution_ru — русский текст разрешения противоречия Баг

Drawer · contradictions

В данных для contradictions есть поле resolution_ru с русским текстом разрешения — но сейчас используется resolution (английский). Это баг: весь интерфейс на русском, а блок разрешения — единственный на английском.

Исправление — одна строка: заменить event.resolution на event.resolution_ru ?? event.resolution (fallback на английский если русского нет).

Б-2 articulated_by — кто поставил проблему Средний

Drawer · problems

Поле содержит массив источников проблемы: ["government", "academic", "regulator"]. Для аналитика, изучающего политический контекст реформ, это важный атрибут — регуляторная проблема, поднятая академическим сообществом, и проблема, инициированная самим регулятором — имеют разный вес.

Отображать в drawer под основным текстом, перед источниками, как строку тегов:

В drawer для проблем
Поставили проблему регулятор академическое сообщество

Значения локализовать: government → «правительство», academic → «академическое сообщество», regulator → «регулятор», market_participants → «участники рынка».

Б-3 problem_addressed + calibration_debate — контекст параметра как инструмента Средний

Drawer · parameters_as_tools

Два взаимосвязанных поля, которые делают раздел «Параметры как инструменты» по-настоящему аналитическим:

  • problem_addressed — какую проблему решает данный параметр («High barriers for SME listings in EU markets»)
  • calibration_debate — как шла дискуссия о числовых значениях («Set to €1.0m floor to match EU minimums…»)

Отображать в drawer как отдельные секции под основным текстом:

Структура drawer для parameters_as_tools
Какую проблему решает
High barriers for SME listings in EU markets
Дискуссия о настройке
Set to €1.0m floor to match EU minimums...

Показывать секцию только если поле не пустое.

Б-4 opposition — контраргументы к реформе Средний

Drawer · reforms

Поле содержит позицию противников реформы — академические данные, опасения участников рынка, критику со стороны инвесторов. Без этого drawer реформы показывает только обоснование (одностороннюю картину), что снижает аналитическую ценность.

Добавить в drawer реформы как отдельную секцию после основного текста, перед источниками:

Секция в drawer для reforms
Контраргументы
Later academic evidence showed deterioration of the information environment...

Показывать секцию только если поле не пустое. Лёгкий красный фон — сигнал «осторожно, есть противоположная позиция», не тревога.

Что не добавлять

Из аудита разработчик отметил два пункта как ненужные — комментирую:

  • Данные площадок (venue_card.json) на карточке юрисдикции — намеренно не показываются. Переход на площадку — следующий уровень иерархии.
  • Источники уровня карточки — отсутствуют в jurisdiction_card.json структурно. Это проблема пайплайна, над которой ведется отдельная работа - потеряно большое количество ссылок на источники. Ведется работа над восстановлением данных, после чего будет возврат к тому, чтобы корректно отображать источники

Порядок выполнения: начать с Б-1 (баг, одна строка). Затем А-1 (высокий приоритет, важно для понимания архитектуры допуска). Остальные — по очереди в рамках текущего спринта.

Решения по системе источников

UX-дизайнер → Tech Lead В ответ на: sources-ux-escalation.md Март 2026

Главный вывод эскалации: исходный дизайн (per-block кнопки + суперскрипты) проектировался под 2–5 источников на блок. Реальный масштаб — 38–94 источника на юрисдикцию без блочной атрибуции. Это принципиально другая ситуация, требующая пересмотра архитектуры отображения источников, а не просто доработки компонента.

Решения по вопросам

В-1 Расположение источников в карточке юрисдикции Новый вариант

Ни вариант А (конец вкладки «Юрисдикция»), ни per-block кнопки не подходят. 38–94 ссылки в конце вкладки — это не сноски, это библиография. Per-block кнопки без атрибуции — обман пользователя: кнопка «источники» в шапке блока «Регулятор» будет вести ко всем 78 источникам юрисдикции целиком.

Решение: отдельная вкладка «Источники». Добавить четвёртую вкладку на карточке юрисдикции:

Юрисдикция Регуляторный анализ 26 Термины 23 Источники 57

Счётчик в бейдже вкладки — общее количество L1-источников. Внутри вкладки — список с поиском и (после В-3) фильтром по типу.

В-2 Drawer регуляторного анализа — источники на запись Вариант А

Вариант А: общий блок «Источники анализа» — но не в drawer каждой записи, а как отдельная секция в конце вкладки «Регуляторный анализ» (под списком/таймлайном). Это честно отражает структуру данных: один пул источников на весь раздел анализа.

В drawer отдельной записи источники не показывать — нет per-record attribution, вставлять туда общий пул из 23–41 источников будет вводить в заблуждение (выглядит как «источники этой конкретной реформы», а это не так).

Старое строковое поле source: string в отдельных записях Level4 — можно показывать в drawer как «Первоисточник» если оно не пустое, но это не полноценная система источников.

В-3 Классификация источников по типу Вариант Б

Вариант Б: попросить пайплайн добавить type — автоматически по домену. Это несложная автоматизация: словарь domain → type. При 57–94 источниках фильтр по типу — реальная необходимость, без него список неудобен.

До получения type от пайплайна — реализовать список без фильтра. Фильтр добавить отдельным шагом.

В-4 L3 citations на уровне параметров — карточка площадки Вариант А

Вариант А: таблица маппинга field-ключей на читаемые лейблы. Per-parameter sources на карточке площадки — наиболее ценное место для источников: пользователь смотрит конкретный параметр (например «минимальный free float»), и именно тут ему нужно знать откуда цифра.

Пайплайн должен предоставить список всех используемых field-ключей. На их основе составляется таблица маппинга. Это разовая работа.

Отображение: маленький тег-ссылка рядом с ячейкой параметра → клик открывает список citations для этого поля.

В-5 Масштаб — режим работы с источниками Подтверждаю вывод

Подтверждаю вывод разработчика: отдельная вкладка «Источники» — правильный архитектурный ответ на реальный масштаб. Это не «сноски для верификации», это полноценная библиография исследования.

Вкладка не конфликтует с существующей структурой. Per-block кнопки из исходного дизайна — убрать, они проектировались под другие данные.

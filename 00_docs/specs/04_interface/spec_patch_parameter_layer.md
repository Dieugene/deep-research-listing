## Патч 1. Раздел 3.1.3 — Вход «от параметра»

### Было:

> **Шаг 1. Выбор параметра.** Каталог параметров, сгруппированных по блокам матрицы 4×5 (фаза ЖЦ × тип содержания). Пользователь выбирает конкретный параметр (free float, минимальная капитализация, срок рассмотрения заявки и т.д.).

### Стало:

**Шаг 1. Выбор параметра.** Каталог — словарь параметров (П01–П23+), сгруппированных по пяти категориям:

| Категория | Параметры | Примеры |
|-----------|-----------|---------|
| Количественные к инструменту | П01–П07 | Free float, min капитализация, min число акционеров, min цена акции |
| Количественные к эмитенту | П08–П12 | Финансовая история, требования к прибыли, к активам, к выручке |
| Качественные к эмитенту | П13–П14 | Корпоративное управление, аудитор/стандарты отчётности |
| Инфраструктурные | П15–П17 | Спонсор, маркет-мейкер, проспект |
| Ограничительные механизмы | П18–П19 | Lock-up, escrow |

Специальные режимы (П20–П23: SPAC, WVR, иностранный эмитент, фонды) — не отдельные строки каталога, а модификаторы. Пользователь выбирает базовый параметр, затем может переключиться на модификатор (см. патч 4).

Перечень параметров — открытый, расширяется при пилотировании. В интерфейсе: параметры без данных отображаются серым с индикатором «данные не собраны».

## Патч 2. Раздел 4.3 — Матрица 4×5, micro reading

### Было:

> **Верхний блок — описательный текст.** Результат исследования в свободной форме. Может содержать параметры, процедуры, условия — но не в виде отдельных полей.

### Стало:

**Содержание ячейки — секции по параметрам из словаря.**

При раскрытии ячейки матрицы 4×5 (например: «Первичный допуск × Требования») пользователь видит не монолитный текст, а перечень параметров, релевантных данной ячейке. Каждый параметр — свёртываемая секция.

Структура секции параметра:

```
[П01] Free float
├── Что установлено: 20%, исключаются пакеты инсайдеров >5%
├── Как рассчитывается: по реестру на дату допуска, верификация через escrow
├── Альтернативы: нет
├── Варьируется: нет (единый порог)
├── Связки: → П04 (min число акционеров = 300)
├── Источник: ASX Listing Rules, Ch. 1, s. 1.1 [ссылка]
└── [Модификаторы: SPAC → ...]  (если применимо)
```

Шесть вопросов описания — не формальные поля, а структурирующие рамки для текстового описания. Текст внутри каждого вопроса — свободной формы.

**Связки параметров.** Если параметры образуют связку (min цена × min число акций = неявный денежный порог), они отображаются рядом с визуальным соединителем: общая рамка, линия, или скобка с пояснением совокупного эффекта. Пример:

```
┌─ Связка: неявный денежный порог ──────────────────────┐
│  [П05] Min цена акции: CAD $0.10                      │
│  [П07] Min объём выпуска: 1,000,000 акций             │
│  → Совокупный эффект: неявный минимум CAD $100,000     │
└───────────────────────────────────────────────────────┘
```

Связки фиксируются при сборе данных (вопрос 5 протокола) и отображаются автоматически.

**Параметры, нерелевантные данной ячейке,** не отображаются (free float нерелевантен для ячейки «Поддержание × Санкции»). Перечень релевантных параметров определяется при заполнении.

**Источники** привязаны к конкретной секции параметра (не к ячейке в целом).

## Патч 3. Раздел 4.4 — Сравнительная таблица (вход «от параметра»)

### Было:

> - Строки отсортированы по значению параметра (не по алфавиту).
> - Цветовая шкала: от мягкого к жёсткому (или от низкого к высокому).

### Стало:

#### Группировка по типу конструкции (вместо числовой сортировки)

Параметры не сводимы к единой единице измерения (предпосылка отображения №10). Сравнительная таблица организована как **группировка по типу конструкции**, а не как числовая сортировка.

Пример для П01 (free float):

| Тип конструкции | Юрисдикции | Значения |
|-----------------|-----------|----------|
| **Процентный порог (фиксированный)** | ASX, LSE, HKEX, MOEX... | 20%, 10%, 25%, 10%... |
| **Денежный порог free float** | NYSE, NASDAQ... | $100M MVPHS, $45M... |
| **Скользящая шкала** | SGX, JSE... | 12%/15%/20% от cap... |
| **Нет прямого требования** | ... | ... |

Внутри группы — сортировка по числовому значению (если применимо). Между группами — сортировка невозможна и не имитируется.

#### Macro reading

Цветовая кодировка — **по типу конструкции**, а не по шкале «мягкий → жёсткий»:

| Тип конструкции | Цвет |
|-----------------|------|
| Процентный порог | Синий |
| Денежный порог | Зелёный |
| Скользящая шкала | Золотой |
| Качественный критерий | Фиолетовый |
| Нет требования | Серый |

Пользователь мгновенно видит: в каком кластере юрисдикций доминирует процентный подход, в каком — денежный. Это информативнее числовой шкалы.

Дополнительно: столбец кластерной принадлежности (из основной спецификации) сохраняется. Пользователь видит корреляцию (или её отсутствие) между институциональным кластером и типом конструкции параметра.

#### Индикация связок

Если выбранный параметр входит в связку — в заголовке таблицы пометка: «П05 (min цена акции) → образует связку с П07 (min объём выпуска) в N юрисдикциях». Ссылка на параллельный просмотр связанного параметра.

#### Фильтрация

Без изменений (по кластеру, по классу инструмента, по уровню листинга). Добавляется: **фильтр по типу конструкции** — пользователь может оставить только юрисдикции с процентным подходом для детального сравнения чисел внутри одного типа.

## Патч 4. Новый элемент — переключатель специальных режимов

В спецификации отсутствовал. Добавляется.

**Расположение:** карточка площадки и раскрытая ячейка матрицы 4×5.

**Функция:** показать, как базовые параметры модифицируются для специальных категорий (SPAC, WVR/dual-class, иностранный эмитент, инвестиционные компании/фонды).

**Визуализация:** переключатель (tabs или dropdown) в верхней части блока параметров:

```
[ Базовый режим | SPAC | WVR | Иностранный эмитент ]
```

По умолчанию — «Базовый режим». При переключении:

- Параметры, которые не изменяются, остаются без изменений.
- Параметры, которые модифицированы, подсвечиваются diff-стилем: зачёркнутое базовое значение → новое значение модификатора. Пример: «free float: ~~25%~~ → 10% для SPAC».
- Параметры, которые добавляются (специфичные для режима), появляются с пометкой «только для [режим]».
- Параметры, которые снимаются (не применяются в режиме), отмечаются как «не применимо для [режим]».

Не все площадки имеют все специальные режимы. Неактивные переключатели — серые, с tooltip «режим не предусмотрен на данной площадке».

Предпосылка отображения №12: специальные режимы — не отдельные строки таблицы, а модификаторы базовых параметров.

## Патч 5. Раздел 8.1 — Источники

### Дополнение:

Источники привязываются не только к ячейкам матрицы 4×5, но и к отдельным секциям параметров внутри ячеек. Это уточняет гранулярность:

| Уровень привязки | Пример |
|------------------|--------|
| Институциональный фактор | WGI 2024 → Ф4 для UK |
| Маппинг терминов | FCA Handbook → маппинг Б03 для UK |
| Ячейка матрицы 4×5 (целиком) | — (устаревший уровень, сохраняется для обратной совместимости) |
| **Секция параметра внутри ячейки** | ASX Listing Rules, Ch. 1 → П01 для ASX/Main/Акции/Допуск |
| Данные 4-го этапа | Consultation paper FCA → рег. цели UK |

Таблица `source_link` в базе данных должна поддерживать привязку к `parameter_value` (не только к `lifecycle_content`).

## Патч 6. Раздел 10.1 — Модель данных

### Новые сущности:

| Сущность | Описание | Связи |
|----------|----------|-------|
| `parameter` | Словарь параметров (П01–П23+). Справочная таблица. | → `parameter_category` (M:1) |
| `parameter_category` | 5 категорий (количественные к инструменту, к эмитенту, качественные, инфраструктурные, ограничительные) | → `parameter` (1:M) |
| `parameter_value` | Описание конкретного параметра в конкретной ячейке. Заменяет монолитный текст `lifecycle_content`. | → `admission_regime` (M:1), → `lifecycle_phase` (M:1), → `parameter` (M:1), → `source` (M:M), → `regime_modifier` (M:1, nullable) |
| `parameter_link` | Связки между параметрами в конкретной ячейке | → `parameter_value` (M:M, self-referencing), + `link_description` (текст: описание совокупного эффекта) |
| `regime_modifier` | Специальные режимы: SPAC, WVR, иностранный эмитент, фонды | Справочная таблица (4 записи для v0) |
| `construction_type` | Тип конструкции параметра (процентный порог, денежный порог, скользящая шкала, качественный критерий, нет требования) | → `parameter_value` (1:M) |

### Изменения существующих сущностей:

**`lifecycle_content`** — не удаляется, но меняет роль. Ранее: основной контейнер текста ячейки. Теперь: контейнер для текста, не привязанного к конкретному параметру (вводные замечания, общие комментарии по ячейке). Основной объём данных переносится в `parameter_value`.

### Схема связей (уточнённая):

```
admission_regime (площадка × уровень × инструмент)
    ↓
lifecycle_content (фаза ЖЦ × тип содержания = ячейка матрицы)
    ↓
parameter_value (конкретный параметр в ячейке)
    ├── → parameter (из словаря)
    ├── → construction_type (тип конструкции)
    ├── → regime_modifier (NULL = базовый, или SPAC/WVR/...)
    ├── → source (M:M)
    ├── → parameter_link (связки с другими parameter_value)
    └── text_fields:
        ├── what_established (что установлено)
        ├── how_calculated (как рассчитывается)
        ├── alternatives (альтернативы)
        ├── variations (варьируется ли)
        ├── general_notes (прочие замечания)
        └── (все поля — текстовые, свободной формы)
```

Примечание: 6 вопросов протокола не обязательно хранить как 6 отдельных полей в базе. Альтернатива — единое текстовое поле с разметкой (markdown с заголовками вопросов). Решение — при проектировании базы, в зависимости от того, нужна ли фильтрация/поиск по отдельным вопросам.

**Версия:** 0.1  
**Дата:** 2026-03-05  
**Статус:** Рабочий документ. Является основой для проектирования базы данных и разработки интерфейса.

## 2. Общая структура интерфейса

### 2.1. Четыре режима доступа

Система предоставляет четыре режима доступа к данным. Каждый режим — самостоятельный раздел с собственной навигацией, но связанный перекрёстными ссылками с остальными.

| # | Режим | Когнитивная задача | Точки входа |
|---|-------|--------------------|-------------|
| 1 | **Справочник** | Быстрое целевое обращение: «покажи мне конкретное» | От инструмента, от юрисдикции/площадки, от параметра |
| 2 | **Сравнительный анализ** | Медленное сравнительное мышление: «покажи похожие и различающиеся» | От кластера институциональных факторов |
| 3 | **Проблемный анализ** | Целеориентированное мышление: «как решается эта проблема» | От проблемы / регуляторной цели РФ |
| 4 | **Бот** | Произвольные запросы | Текстовый ввод |

**Принцип Тафти:** Справочник и аналитические режимы (2, 3) разделены, потому что обслуживают разные когнитивные режимы. Справочник — для поиска (быстрое целевое обращение). Аналитика — для рассматривания (медленное сравнительное мышление). Один интерфейс не может обслуживать оба.

### 2.2. Главная страница

Минимальная. Четыре зоны входа:

- **Справочник** — блок с переключателем точки входа (по умолчанию — «от инструмента»).
- **Сравнительный анализ** — превью кластерной визуализации (миниатюра scatter plot / heatmap).
- **Проблемный анализ** — карта проблем (превью).
- **Бот** — поле ввода вопроса.

Статистика: «47 юрисдикций, 65 площадок, N заполненных ячеек. Последнее обновление: дата». Индикатор зрелости данных.

### 2.3. Перекрёстные ссылки — несущая конструкция

Все режимы связаны двунаправленными ссылками:

| Из | В | Тип связи |
|----|---|-----------|
| Справочник (ячейка матрицы 4×5) | Проблемный анализ | «Связанные проблемы РФ» — список релевантных ПА/ПБ |
| Справочник (ячейка матрицы 4×5) | Сравнительный анализ | «Кластер юрисдикции» — переход к кластерному представлению |
| Справочник (карточка юрисдикции) | Сравнительный анализ | «Показать в кластере» — позиция юрисдикции на scatter plot |
| Проблемный анализ (проблема → юрисдикция) | Справочник | Прямая ссылка на ячейку матрицы 4×5 (класс × фаза) |
| Сравнительный анализ (кластер) | Справочник | «Сравнить параметры внутри кластера» — справочник с фильтром |
| Любой экран | Бот | Боковая панель, контекстно-зависимая |

## 3. Режим «Справочник»

### 3.1. Три точки входа

Три точки входа — три маршрута к одним и тем же данным. Нет дублирования контента.

#### 3.1.1. Вход «от инструмента» (основной)

Навигационная цепочка: **Класс инструмента → Юрисдикция/площадка → Уровень листинга → Матрица 4×5 → Ячейка.**

**Шаг 1. Выбор класса инструмента.** Четыре карточки: Акции, Облигации, Фонды, Депозитарные расписки. Каждая — с индикатором заполненности (например, «38 из 47 юрисдикций»).

**Шаг 2. Список площадок с ключевыми параметрами.** Таблица micro/macro reading:
- Строки: площадки, сгруппированные по юрисдикциям.
- Столбцы: 5–7 ключевых параметров для данного класса инструментов.
- Цветовая кодировка: паттерн жёсткости виден при macro reading.
- Иконка кластерной принадлежности справа от каждой юрисдикции.
- Фильтр по подклассу инструмента (В03) — не уровень навигации, а фильтр в таблице.

**Шаг 3. Карточка площадки** (см. п. 4.2).

**Шаг 4. Матрица 4×5** (см. п. 4.3).

#### 3.1.2. Вход «от юрисдикции/площадки»

Навигационная цепочка: **Юрисдикция → Карточка юрисдикции → Площадка → Карточка площадки → далее как в 3.1.1.**

**Шаг 1. Список юрисдикций.** Компактная таблица с мини-профилем: название, правовая семья (Ф1), кластерная принадлежность (цвет), количество площадок, индикатор заполненности. Фильтрация: по кластеру, по правовой семье, по наличию данных.

Юрисдикция — контейнер, площадка — основной объект навигации. Если площадка одна — переход к ней автоматический. Если площадок несколько — список с кратким описанием различий.

**Шаг 2. Карточка юрисдикции** (см. п. 4.1).

**Шаг 3. Карточка площадки** (см. п. 4.2).

#### 3.1.3. Вход «от параметра»

Навигационная цепочка: **Параметр → Сравнительная таблица → Клик по ячейке → контекст (карточка площадки, матрица 4×5).**

**Шаг 1. Выбор параметра.** Каталог параметров, сгруппированных по блокам матрицы 4×5 (фаза ЖЦ × тип содержания). Пользователь выбирает конкретный параметр (free float, минимальная капитализация, срок рассмотрения заявки и т.д.).

**Шаг 2. Сравнительная таблица** (см. п. 4.4).

## 4. Визуальные шаблоны

### 4.1. Карточка юрисдикции

Шаблон small multiple — одинаковая структура для всех 47 юрисдикций. Должна помещаться на экран целиком (без скролла) для возможности сравнения бок о бок.

#### Блок А. Заголовок и идентификация

- Название юрисдикции.
- Кластерная принадлежность: цветовой индикатор + название кластера.

#### Блок Б. Институциональные факторы

12 факторов в 4 группах. Визуализация адаптирована к типу шкалы (требование: регистр институциональных факторов, п. 2):

**Блок I. Правовая система (Ф1–Ф3):**
- Ф1 (правовая семья) — категориальный: текстовая метка + цветовая кодировка.
- Ф2 (ASDI, шкала 0–1) — непрерывный: числовое значение + точка на горизонтальной шкале.
- Ф3 (private enforcement) — категориальный: текстовая метка + цветовая кодировка.

**Блок II. Качество институтов (Ф4–Ф6):**
- Три индекса WGI по единой шкале −2.5…+2.5.
- Визуализация: три горизонтальных бара рядом (grouped bar) с возможностью свёртки в композитный индикатор (требование: регистр, п. 3).

**Блок III. Структура рынка (Ф7–Ф10):**
- Ф7 (капитализация/ВВП, процентный) — числовое значение + sparkline-точка на оси.
- Ф8 (концентрация владения) — категориальный: метка + цвет.
- Ф9 (инвесторская база) — категориальный: метка + цвет.
- Ф10 (конкурентная структура площадок) — категориальный: метка + цвет + визуальная пометка «авторская шкала» (требование: регистр, п. 6).

**Блок IV. Архитектура регулирования (Ф11–Ф12):**
- Категориальные: метка + цвет.
- Визуальная пометка пограничного статуса (институциональный / регуляторный) (требование: регистр, п. 10).

**Отсутствие данных:** явная индикация «н/д» (не пустое поле и не «0»). Особенно критично для Ф2 и Ф9 (требование: регистр, п. 7).

#### Блок В. Архитектура допуска

- Признак архитектуры (Г04): объединённый / раздельный / смешанный.
- Визуально: компактная схема «РЕГУЛЯТОР → БИРЖА» или «БИРЖА (SRO)» и т.д.
- Одинаковый формат для всех юрисдикций — мгновенное сравнительное чтение (требование: регистр основной, п. 9).

#### Блок Г. Наднациональная рамка (если применимо)

- Для EU-стран: блок «Наднациональное регулирование» со ссылкой на общий материал по EU-регулированию (MiFID II, Prospectus Regulation, Transparency Directive).
- Индикация: какие параметры определены на уровне EU, какие — на национальном.
- Визуально: два цвета (или иконки) в полях данных — «EU-минимум» и «национальная надстройка».

#### Блок Д. Маппинг терминов (уровень юрисдикции)

Таблица маппинга архитектурных понятий метаязыка на местную терминологию. Свёртываемый блок (overlay).

Понятия, маппируемые на уровне юрисдикции: Г02 (официальный листинг), Г03 (допуск к торгам), Г04 (архитектура допуска), Б03 (листинговый орган), Б04 (регулятор).

Формат: | Понятие метаязыка | Местный термин (оригинал) | Местный термин (перевод) | Источник |

#### Блок Е. Площадки

Список площадок юрисдикции: название, тип (А03: regulated market / MTF / OTF), количество уровней листинга, классы инструментов (иконки). Клик — переход к карточке площадки.

#### Блок Ж. Данные четвёртого этапа (проблемно-ориентированный)

Три текстовых блока (свёртываемые), каждый с источниками:
1. Регуляторные цели, обсуждавшиеся в юрисдикции.
2. Связь параметров с целями.
3. Релевантность для РФ (маппинг на проблемы ПА/ПБ).

#### Блок З. Сводный реестр источников

Все источники, использованные по данной юрисдикции. Нумерованный список: название документа → ссылка. Привязка к конкретным блокам данных через сноски.

### 4.2. Карточка площадки

#### Заголовок

- Название площадки (местное + метаязык, если различаются).
- Юрисдикция (ссылка на карточку юрисдикции).
- Оператор (Б02), если отличается от названия площадки.
- Тип рынка (А03): regulated market / MTF / OTF / иное.

#### Сегментация

Визуальная карта: два измерения навигации (требование: регистр основной, п. 3):

- **Ось 1 — Уровень листинга (А05):** Main / Standard / Growth и т.д. Иерархия строгости.
- **Ось 2 — Специализированный сегмент (А04):** тематические надстройки (ESG, МСП, технологический).

Для площадок без тиерированного листинга (характерно для облигаций, требование: регистр основной, п. 4) — отображается как единый блок без иерархии.

В каждой ячейке карты — иконки классов инструментов (4 иконки, активные/неактивные). Клик по ячейке — переход к матрице 4×5.

#### Маппинг терминов (уровень площадки)

Свёртываемая таблица маппинга операционных понятий.

Понятия, маппируемые на уровне площадки: А04 (специализированный сегмент), А05 (уровень листинга), Г01 (режим допуска), названия конкретных уровней/сегментов.

Формат: | Понятие метаязыка | Местный термин (оригинал) | Местный термин (перевод) | Источник |

#### Вторичный допуск (Г06)

Не отдельная навигация. Внутри карточки площадки — индикатор: «Специальный режим вторичного допуска: да/нет». Если да — ссылка на перечень исключений/упрощений относительно стандартного режима (требование: регистр основной, п. 8).

### 4.3. Матрица 4×5

Контекст: конкретная ячейка исследования — площадка × уровень листинга × класс инструмента (Г01).

#### Представление матрицы

Таблица 4 строки × 5 столбцов.

**Строки (фазы ЖЦ, Г07):**
1. Первичный допуск (Г07.1)
2. Поддержание (Г07.2)
3. Приостановка (Г07.3)
4. Исключение (Г07.4)

**Столбцы (тип регулятивного содержания):**
1. Требования (Д01)
2. Процедуры (Д02)
3. Мониторинг и надзор (Д03)
4. Санкции и enforcement (Д04)
5. Раскрытие информации (Д05)

#### Macro reading

Каждая ячейка имеет три визуальных состояния (первая версия):

| Состояние | Цвет | Значение |
|-----------|------|----------|
| Заполнена | Синий (интенсивность пропорциональна объёму текста) | Данные собраны |
| Не заполнена | Светло-серый | Данные не получены |
| Не применимо | Заштрихованный | Ячейка не релевантна для данного режима |

Примечание: в будущих версиях возможен переход к экспертной оценке «уровня жёсткости» (мягкий / средний / жёсткий) как метаданных поверх текста, с визуализацией через цветовую шкалу. Для первой версии приоритет — заполненность.

#### Micro reading (раскрытие ячейки)

Клик по ячейке — раскрытие содержания:

**Верхний блок — описательный текст.** Результат исследования в свободной форме. Может содержать параметры, процедуры, условия — но не в виде отдельных полей.

**Нижний блок — источники.** Нумерованный список: название документа → ссылка. С привязкой к конкретным утверждениям в тексте (как сноски).

**Фильтр по подклассу инструмента (В03).** Если внутри ячейки есть различия по подклассам (например, для корпоративных и суверенных облигаций — разные пороги), они отображаются как секции внутри текста или как переключатель подкласса.

#### Контекстный overlay

Кнопка «Институциональный контекст» — боковая панель с мини-версией блока Б из карточки юрисдикции. Пользователь видит параметры и контекст одновременно (принцип adjacency).

Кнопка «Связанные проблемы РФ» — список релевантных проблем ПА/ПБ со ссылками в проблемный анализ.

#### Д06 (Регуляторное обоснование)

Не выделяется как отдельное поле в матрице. Регуляторное обоснование является элементом аналитического слоя: появляется в данных четвёртого этапа (блок Ж карточки юрисдикции) и в проблемном анализе, а не в справочных ячейках.

### 4.4. Сравнительная таблица (вход «от параметра»)

#### Структура

- Строки: площадки, сгруппированные по юрисдикциям.
- Основной столбец: значение выбранного параметра.
- Дополнительный столбец: кластерная принадлежность юрисдикции.

#### Macro reading

- Строки отсортированы по значению параметра (не по алфавиту).
- Цветовая шкала: от мягкого к жёсткому (или от низкого к высокому).
- Паттерн виден мгновенно: группы юрисдикций с близкими значениями.

#### Фильтрация

- По кластеру: выбрал кластер — таблица сужается до юрисдикций этого кластера.
- По классу инструмента: если параметр различается по классам.
- По уровню листинга: если параметр различается по уровням.

#### Индикация наднационального регулирования

Для EU-стран: визуальная пометка, если значение определено на наднациональном уровне (не национальный выбор). Позволяет отличить «Германия и Франция выбрали одинаковый порог» от «это EU-директива».

#### Переходы

Клик по строке → карточка площадки или матрица 4×5 в контексте выбранного параметра.

## 5. Режим «Сравнительный анализ»

### 5.1. Назначение

Инструмент для работы с кластерами юрисдикций по институциональным факторам. Реализует рекомендацию Рейгина: анализировать не юрисдикции, а конфигурации условий.

### 5.2. Основная визуализация

Два переключаемых представления:

**Scatter plot:**
- Две оси — два фактора (по выбору пользователя).
- Точки — юрисдикции.
- Цвет — кластерная принадлежность.
- Hover — мини-карточка юрисдикции (название, ключевые факторы).
- Клик — переход к полной карточке юрисдикции.
- Панель выбора факторов для осей — минимальный конструктор.

**Heatmap:**
- Строки — юрисдикции (отсортированные по кластерам).
- Столбцы — институциональные факторы (12).
- Цвет — значение фактора.
- Кластерная структура видна как блоки одинакового цвета.
- Компактнее scatter plot; показывает все факторы одновременно.

### 5.3. Ключевые функции

**Фильтрация справочника по кластеру:** выбрал кластер → кнопка «сравнить параметры внутри кластера» → переход в справочный режим с предустановленным фильтром.

**Карточки бок о бок (small multiples):** выбрал 2–4 юрисдикции → видишь их карточки (п. 4.1) рядом в одной строке. Одинаковая структура — глаз мгновенно видит различия.

**Предупреждение о кросс-кластерном сравнении:** если пользователь в справочнике выбирает юрисдикции из разных кластеров — система показывает: «Юрисдикции в разных кластерах, институциональные условия различаются по факторам X, Y, Z».

### 5.4. Outcome variable

Визуализация outcome variable (приток акционерного капитала при сохранении защиты розничных инвесторов): отдельный слой на scatter plot. Размер точки или дополнительный цветовой канал — значение outcome. Позволяет видеть: какие конфигурации факторов приводят к желаемому результату (требование: регистр институциональных факторов, п. 8).

## 6. Режим «Проблемный анализ»

### 6.1. Назначение

Вход от проблем и целей российского регулирования. Данные — результат четвёртого этапа исследования (после сбора справочных материалов).

### 6.2. Навигационная структура

**Уровень 1. Карта проблем.**

Группировка:

- **Конфликты целей** (4 конфликта):
  - К1: Массовый выход эмитентов (Ц1, Ц3) vs Защита розничных инвесторов (Ц4)
  - К2: Доступность листинга для МСП (Ц2, Ц5) vs Качество рынка
  - К3: Коммерческие интересы биржи vs Регуляторное качество
  - К4: Указные KPI (66% ВВП) vs Рыночная реальность (24,1% ВВП)

- **Проблемы, артикулированные регулятором** (ПА1–ПА5).

- **Проблемы, артикулированные рынком** (ПБ1–ПБ10).

- **Слепые зоны** (делистинг, continuing obligations, облигации/фонды).

Каждая проблема отмечена: класс инструментов, фаза ЖЦ, уровень консенсуса (где применимо).

**Уровень 2. Детализация проблемы.**

Пользователь выбирает проблему (например, ПБ1 — рассинхронизация free float). Видит:

- Формулировка проблемы.
- Привязка: класс инструментов + фаза ЖЦ.
- Связь с целями (Ц1–Ц5) и конфликтами (К1–К4).
- Список юрисдикций, по которым собраны данные четвёртого этапа по этой проблеме.
- По каждой юрисдикции: краткая выдержка — какие цели обсуждались, какие параметры выбраны, почему.
- Источники.

**Уровень 3. Переход в справочник.**

Клик по юрисдикции — переход к конкретным справочным данным. Поскольку проблема привязана к классу и фазе, система открывает нужную ячейку матрицы 4×5. Для ПБ1: акции → первичный допуск → требования → free float.

### 6.3. Обратные ссылки

Из справочника (ячейки матрицы 4×5) — ссылки «Связанные проблемы РФ» → список релевантных ПА/ПБ.

## 7. Бот

### 7.1. Расположение

Боковая панель, доступная с любого экрана. Поле ввода + история диалога.

### 7.2. Контекстная зависимость

Бот учитывает текущий экран пользователя. Если пользователь находится на карточке HKEX и спрашивает «а как здесь с free float?» — бот понимает контекст.

### 7.3. Три функции

**Поиск:** «В каких юрисдикциях free float ниже 15%?», «Где облигации не имеют тиерированного листинга?» Замена ручного сканирования таблиц.

**Сравнение:** «Сравни требования к IPO на LSE и HKEX для акций». Бот собирает данные из двух карточек и кладёт рядом — принцип adjacency, реализованный динамически.

**Генерация фрагментов доклада:** «Напиши абзац о том, как юрисдикции с высокой концентрацией владения компенсируют это через требования к free float». Прямая помощь авторам доклада.

### 7.4. Приоритет реализации

После справочного и аналитических режимов. Требует: структурированные данные в базе + LLM с доступом через function calling.

## 8. Сквозные элементы

### 8.1. Источники

Источники — сквозная сущность, присутствующая в каждом блоке данных.

**Хранение в базе:** отдельная таблица `sources`, связанная с любой сущностью через many-to-many (таблица `source_links`).

**Поля источника:**
- ID
- Название документа (на языке оригинала)
- Название документа (перевод, если применимо)
- URL
- Тип (первичное законодательство / rulebook биржи / guidance регулятора / consultation paper / аналитический отчёт / новостная публикация)
- Дата публикации
- Дата обращения (когда данные были извлечены)

**Отображение в интерфейсе:**
- Иконка-сноска рядом с каждым блоком данных.
- Клик → список источников с названиями и ссылками.
- По каждой юрисдикции — сводный реестр всех источников (блок З карточки юрисдикции).

**Привязка к утверждениям:** внутри описательного текста (ячейки матрицы 4×5) — сноски на конкретные источники (по номеру из реестра юрисдикции).

### 8.2. Наднациональное регулирование

Наднациональная рамка — отдельная сущность в базе, не точка входа в навигации.

**Хранение:** таблица `supranational_frameworks` (EU, потенциально другие). Связь: юрисдикция → наднациональная рамка (many-to-one).

**Отображение:**
- В карточке юрисдикции: блок Г (если применимо).
- В справочных данных: индикация «наднациональный минимум» vs «национальная надстройка».
- В сравнительных таблицах: пометка, если значение определено наднациональным актом.

### 8.3. Маппинг терминов

Двухуровневый:

| Уровень | Что маппируется | Понятия ядра | Где отображается |
|---------|-----------------|-------------|------------------|
| Юрисдикция | Архитектурные понятия | Г02, Г03, Г04, Б03, Б04 | Блок Д карточки юрисдикции |
| Площадка | Операционные понятия | А04, А05, Г01 + названия уровней/сегментов | Маппинг в карточке площадки |

Формат записи: понятие метаязыка → местный термин (оригинал) → местный термин (перевод) → источник.

### 8.4. Индикация отсутствия данных

Три различаемых состояния:

| Состояние | Значение | Визуализация |
|-----------|----------|-------------|
| Заполнено | Данные собраны | Содержательный цвет/текст |
| Не получены | Данные недоступны (язык, отсутствие источника) | «н/д» + специальный маркер |
| Не применимо | Ячейка нерелевантна (нет тиерированного листинга, нет мониторинга на фазе допуска) | Штриховка |

Пустое поле и «0» никогда не используются для обозначения отсутствия данных (требование: регистр институциональных факторов, п. 7).

## 9. Этапы заполнения и влияние на интерфейс

Данные появляются в системе поэтапно. Интерфейс должен корректно работать на каждом этапе, а не только при полном заполнении.

| Этап | Что заполняется | Что работает в интерфейсе |
|------|-----------------|---------------------------|
| 1. Маппинг понятий | Карточки юрисдикций (блок Д), карточки площадок (маппинг) | Вход от юрисдикции; навигация по площадкам; маппинг терминов |
| 2. Институциональные факторы | Блок Б карточек юрисдикций | Кластеризация; сравнительный анализ; фильтрация по кластеру |
| 3. Справочные данные | Матрица 4×5 по ячейкам | Справочник (все точки входа); macro/micro reading; сравнительные таблицы |
| 4. Аналитические материалы | Блок Ж карточек юрисдикций; данные проблемного анализа | Проблемный анализ; перекрёстные ссылки «проблема ↔ справочник» |

**Индикаторы заполненности** присутствуют на всех уровнях навигации: в списке юрисдикций, в карточке площадки, в матрице 4×5. Пользователь всегда видит, насколько данные полны.

| `supranational_framework` | А01 (примечание) | → `jurisdiction` (1:M) |

### 10.2. Ключевые принципы

**Нормализация.** Данные хранятся в нормализованных таблицах, не во вложенных JSON. Это обеспечивает произвольные срезы (основа для будущего конструктора) и корректную работу бота через SQL-запросы.

**Полиморфные связи для источников.** Таблица `source_link` связывает `source` с любой сущностью через пару (entity_type, entity_id). Это позволяет привязать источник к институциональному фактору, к ячейке матрицы, к маппингу терминов — единообразно.

**Мягкие внешние ключи для факторов.** Значения институциональных факторов хранятся в отдельной таблице (не в колонках `jurisdiction`), чтобы допустить расширение набора факторов без миграции схемы.

**Вторичный допуск как модификатор.** Не отдельная сущность. Хранится как атрибут `admission_regime` (булево поле `has_secondary_regime`) + связанный текстовый блок с описанием упрощений.

### 10.3. Подготовка к будущему конструктору

Структура данных должна поддерживать запросы вида: «для всех юрисдикций с Ф8 = 'high concentration' и Ф3 = 'weak enforcement' — показать значения free float на основном уровне листинга для акций».

Это обеспечивается нормализованной схемой + индексами по факторам и параметрам. Конструктор как элемент интерфейса — не в первой версии, но модель данных не должна его блокировать.

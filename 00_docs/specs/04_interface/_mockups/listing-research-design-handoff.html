01 Контекст продукта

Listing Research — аналитическая база регуляторных требований к листингу ценных бумаг по ~47 юрисдикциям и ~120 торговым площадкам. Целевая аудитория — регуляторы, юридические и финансовые аналитики Банка России.

Основная задача интерфейса: сделать плотные структурированные данные читабельными и сравнимыми. Пользователь приходит за конкретной информацией, а не за впечатлением — поэтому дизайн утилитарный, но с характером.

Технический стек: предположительно React + Node.js/Python бэкенд + PostgreSQL. Прототипы сделаны как статический HTML/CSS/JS. CSS-переменные перенесутся напрямую. Таймлайн — чистый JS без библиотек (масштабируется).

Важно: сервис планирует расширяться до ~47 юрисдикций, ~120 площадок. Все компоненты должны работать при любом объёме данных — от 1 площадки до 30+, от 3 событий в таймлайне до 27+.

02 Дизайн-принципы

ПринципЧто это значит на практике
Утилитарность прежде всего Никакой декорации ради декорации. Каждый визуальный элемент несёт смысловую нагрузку. Характер — через типографику и консистентность, не через цвет.
Пользовательская логика, не техническая Данные расположены так, как пользователь думает, а не так, как удобно в базе. Площадки важнее маппинга терминов — несмотря на то что термины «технически» привязаны к юрисдикции.
Масштабируемость Все компоненты должны работать при пустых данных, частичных данных и полных. Пустые юрисдикции показываем с явным статусом «В работе», не молчим.
Источники везде Это регуляторный инструмент. Каждый блок данных обязан иметь доступные источники. Система двухуровневая: суперскрипт на фрагменте + кнопка «N источников» в шапке блока.
Светлая тема основная Аудитория — регуляторы и юристы, не трейдеры. Белый фон = документ = доверие. Длинные тексты лучше читаются на светлом.

06 Система источников

Каждый блок данных обязан иметь источники. Система двухуровневая:

Уровень 1 — суперскрипт внутри текста

Уровень 2 — кнопка «N источников» в шапке блока

Архитектура допуска 3 источника

Противоречие — специальный паттерн

Карточка типа «Противоречие»: две стороны + разрешение
Цель А — Защита инвесторов
С 2013–2014 FCA приоритизировала защиту через структурные гарантии для компаний с контролирующими акционерами.
Цель Б — Привлечение эмитентов
С 2021 приоритет сместился к привлечению: разрешены DCSS, убрано деление на сегменты.
Разрешение
FCA допустила DCSS и заменила деление на сегменты единой категорией — перенастройка, а не полная дерегуляция.

09 Таймлайн регуляторного анализа

Таймлайн — альтернативный режим просмотра регуляторного анализа. Показывает развитие дискурса во времени одним взглядом. Переключается кнопкой «Список / Таймлайн» внутри вкладки, таймлайн — по умолчанию.

Ключевые дизайн-решения

РешениеОбоснование
Единая хронологическая ось без группировки по категориям Категории и так закодированы цветом. Группировка ломает нарратив: пользователю важно видеть, что реформа UKLR 2024 — ответ на проблему 2008–2021, а не отдельная история.
Один элемент — одна строка Несколько элементов на одной строке разрывают линейное восприятие времени. При 27+ элементах (Гонконг) таймлайн высокий, но читаемый.
Все периоды — отрезки (не прямоугольники) Отрезок честнее передаёт «период времени» без ложного ощущения объёма. Унификация убирает визуальную иерархию, которой нет в данных. Прямоугольники создавали ожидание контента внутри.
Подпись выровнена по левой точке отрезка Начало чтения = начало периода. Взгляд не прыгает между идентификацией начала отрезка и центром подписи.
Детализация — drawer-оверлей справа Не сужает таймлайн. Не требует скролла. Накладывается поверх контента, закрывается крестиком или кликом по затемнению. Стандартный паттерн аналитических инструментов.
Drawer начинается под nav + tabs (top: 112px) Сохраняет навигацию доступной при открытом drawer. Backdrop тоже начинается с этой точки.

10 Страница юрисдикции — макет и решения

Общая структура

/* Первый экран (grid 1fr 340px) */
[Архитектура допуска + Регулятор] | [Площадки-миникарточки]

/* Ниже при скролле (grid 1fr 1fr) */
[Институциональные метрики ВБ]   | [Схожие юрисдикции / кластеры]

Ключевые layout-решения

РешениеОбоснование
Архитектура + Регулятор = одна карточка Регулятор — структурированный ответ на вопрос «кто управляет этой системой», логически вложенный в архитектуру допуска. Разделение создавало избыточную вертикаль.
Регулятор — горизонтальная плашка, не таблица 5 коротких атрибутов в таблице занимали ~160px и выглядели пусто. Плашка занимает ~44px.
Площадки в правой колонке первого экрана Площадки — основной пользовательский путь (там про листинг). Должны быть видны без прокрутки. Не в низу страницы, не отдельной вкладкой.
Флаг — SVG Union Jack, не эмодзи Эмодзи флаги рендерятся как «GB» в некоторых конфигурациях Windows+Chrome. SVG работает везде.

# Извлечение параметров из L3-результатов
## Инструкции для постпроцессинга

**Дата:** 2026-03-10
**От кого:** Architect
**Кому:** Tech Lead
**Контекст:** L3-данные по пилотным площадкам собраны. Следующий шаг — извлечение конкретных параметров регулирования и описание того, как они устроены. Настоящий документ определяет: что извлекать, как описывать, что делать с неожиданными находками.

---

## 1. Общая логика

Для каждой ячейки (venue × tier × instrument class) из L3-результатов извлекаются **параметры** — конкретные количественные и качественные требования, которые применяются на данной площадке к данному классу инструментов.

Перечни параметров ниже — это **чеклисты**, а не обязательные схемы. Для каждого параметра допустимы три результата:

| Результат | Значение | Что записать |
|---|---|---|
| **Найден** | Параметр присутствует в L3-данных с конкретным значением | Описание по 6 вопросам (раздел 3) |
| **Не применяется** | Площадка не использует этот параметр для данного класса инструментов | `not_applicable` с кратким пояснением (напр. «no free float requirement for bonds on this venue») |
| **Данные не найдены** | L3-результат не содержит информации по параметру, но нельзя утверждать, что параметр не применяется | `data_not_found` — кандидат на повторный запрос |

**Критически важно:** промпт не должен принуждать LLM заполнять все параметры. Формулировка: «For each parameter in the checklist below, report the value if found in the data, or state that it is not applicable / not found.»

## 3. Структура описания каждого параметра

Для каждого найденного параметра — текстовое описание, покрывающее шесть вопросов. Не табличная раскладка по полям — связный текст.

```
PARAMETER DESCRIPTION TEMPLATE:
For each parameter found in the L3 data, provide a text description covering
these six questions:

1. WHAT IS ESTABLISHED? Numeric threshold, qualitative criterion, or
   combination. In what units (%, count, monetary amount, combination).
   If monetary — in what currency.

2. HOW IS IT CALCULATED? What is included, what is excluded. Cutoff thresholds
   (holdings >5%, >10%). Who verifies the calculation.

3. ARE THERE ALTERNATIVES? Can the requirement be met in another way (either/or).
   Example: "25% free float OR 5% if value ≥ €5M".

4. DOES IT VARY? Does the threshold depend on company size (sliding scale),
   listing tier, issuer type, presence of a market maker?

5. IS IT LINKED TO OTHER PARAMETERS? Does it form a bundle with another
   requirement (min price × min shares = implicit monetary threshold)?
   Does it depend on another requirement being met?

6. SOURCE. Reference to the specific rule, section, or chapter.
```

## 4. Обработка параметров, не входящих в чеклист

При извлечении LLM может обнаружить параметры, которых нет в чеклисте для данного класса инструментов. Это ожидаемо — перечень не претендует на полноту.

**Инструкция для промпта:**

```
UNKNOWN PARAMETERS:
If you find admission requirements or quantitative/qualitative criteria that
do not match any parameter in the checklist above — report them in a separate
section "ADDITIONAL PARAMETERS NOT IN CHECKLIST". For each, provide:
- A short descriptive name
- The same 6-question description as for checklist parameters
- Your best guess at which checklist parameter it is closest to (if any)
```

**Инструкция для постпроцессинга:**

При обработке результатов:
- Параметры из чеклиста → стандартная обработка.
- Параметры из секции ADDITIONAL → записать в лог с тегом `[UNKNOWN_PARAM]`, включая: площадку, класс инструмента, название параметра, описание.
- По итогам прогона — Tech Lead формирует сводку неизвестных параметров и эскалирует на Architect для решения: включить в чеклист (с присвоением ID), признать вариантом существующего параметра, или отложить.

## 5. Различие параметров по фазам жизненного цикла

Один и тот же параметр может иметь **разные значения** на разных фазах:
- Free float при допуске: 25%
- Free float при поддержании: 10% (пониженный порог)
- Free float как основание для исключения: <5%

**Инструкция для промпта:**

```
LIFECYCLE PHASES:
For each parameter, specify which lifecycle phase the value applies to:
- ADMISSION (Г07.1): threshold for initial admission
- CONTINUING (Г07.2): threshold for maintaining listing
- SUSPENSION/REMOVAL (Г07.3/Г07.4): threshold triggering suspension or delisting

If the same parameter has DIFFERENT values for different phases — report each
separately. If the value is the same across phases — state this explicitly.
If a parameter applies only to one phase — state which.
```

## 6. Валидация результатов

После извлечения параметров — автоматическая проверка:

| Проверка | Условие | Действие |
|---|---|---|
| Пустой чеклист | Ни один параметр из чеклиста не найден и не помечен `not_applicable` | `[WARNING]` в лог — вероятно, LLM не получила достаточно данных или промпт некорректен |
| Неожиданное присутствие | Параметр, помеченный «как правило, не применяется» (напр. free float для bonds), найден со значением | `[INFO]` в лог — валидная находка, зафиксировать |
| Все параметры `data_not_found` | Более 70% чеклиста — `data_not_found` | `[WARNING]` — L3-данные, вероятно, неполные; кандидат на повторный запрос с повышенной глубиной |
| Неизвестные параметры | Секция ADDITIONAL не пуста | `[UNKNOWN_PARAM]` в лог — эскалация на Architect |

## 7. Порядок работы

1. Для каждой ячейки определить класс инструмента → выбрать соответствующий чеклист (раздел 2).
2. Сформировать промпт: шаблон описания (раздел 3) + чеклист параметров + инструкции по unknown (раздел 4) + инструкции по фазам (раздел 5).
3. Прогнать на L3-данных пилотных площадок.
4. Выполнить валидацию (раздел 6).
5. Сформировать сводку:
   - Какие параметры найдены, по каким площадкам.
   - Какие параметры `not_applicable` — для каких площадок и классов.
   - Какие `data_not_found` — кандидаты на повторный запрос.
   - Какие неизвестные параметры обнаружены — эскалация на Architect.
